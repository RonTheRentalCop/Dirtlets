Thursday September 10th
- Decided that the robots will stream camera video and sensor data to a central computer instead of performing the main computations onboard each robot.
- Reason for this change: Raspberry Pi computers and similar onboard computing hardware are too expensive to purchase for every robot. The existing ESP32 boards can handle camera streaming, motor control, and basic sensor communication at a lower cost.
- The central computer will perform the expensive operations, including object detection, distance processing, localization, map building, path planning, and combining data from multiple robots in real time.
- The robots will receive movement commands from the central computer. Each robot should still have a local emergency-stop behavior if the connection is lost, so a communication failure does not leave the motors running.
- The first mapping goal is a 2D or 2.5D map using the RPLIDAR, camera video, wheel encoders, and the MPU-650. A full 3D map can be investigated later if the project requires additional depth hardware or a lidar scanning mechanism.
- Possible future deployment concept: a landing craft could act as the central relay and computing station. It could receive signals and sensor data from the deployed robots, stream or compile their data in real time, and send the combined results back to the main base or operator.
- This landing-craft concept is currently a possible future architecture, not a required part of the first prototype.
